# データの配置と手動バックアップ

運用者は定期的に、手動で `data/store/` を丸ごとコピーする。Git のクローンと、実験に使った各版の外部データセットがあれば、このコピーだけでバックアップ時点のプロジェクト全体の実験履歴と保持対象の成果物を復元できることを要件とする。

## 正本と実験の定義

| 配置 | 保持する内容 |
| --- | --- |
| `recipes/`（Git 管理） | コーパスの公式分割や公式のデータ作成手順。分割一覧がコーパスに同梱されている場合は、配布版とコーパス内の相対パスで参照する。 |
| `configs/`（Git 管理） | 再現実験の起動設定。採用するレシピ、モデル、学習条件、評価方法を指定する。 |
| `data/store/` | 正本を含む DB、プロジェクト内のラベル訂正、確定したデータセット版と登録済みレシピ、各実行の確定設定、使用記録、履歴、ログ、保持対象の保存点・成果物、当時のソースを復元するための情報。 |
| `data/work/` | 正本と同じ版の入力から再構築できる索引 DB、キャッシュ、中間ファイル。復元先では空の状態から作り直せる。 |

データセットごとにメタデータとレシピを別テーブルで管理する。版だけが異なる場合はテーブルを共有しても、版ごとに分けてもよい。いずれも、使用したデータセット版を指定すれば当時の分割、ラベル、レシピを取得できるようにする。正本の DB が参照するログや成果物の実体も、復元した `store/` 内で解決できる形で保持する。 [Dataset の詳細設計](../30_detailed_design/05_dataset.md)

## 外部データセットの配置

各計算機で Git 管理の `.env.example` をひな形に `.env` を用意し、コーパスの実体パスを記入する。初回セットアップ時と配置変更時に `make setup-data` を手動で実行し、`data/corpora/<corpus_id>` から実体へのシンボリックリンクを作成・更新してコーパスのメタデータを作る。実験設定にはプロジェクトルートからの相対パスを記録し、起動時に使用するコーパスをその入口から参照できることを確認する。 [Make ターゲット](02_make_and_scripts.md#make-ターゲット)・[設定のパス解決](../30_detailed_design/02_configuration.md#パスの解決)

## バックアップ

1. 進行中の実行を終了または中断する。中断を要求した場合は `status` で停止を確認する。レシピ登録なども含めて `data/store/` への書き込みが完了した状態を、コピーが終わるまで保つ。これで DB の記録と参照先のファイルを同じ時点で取得できる。 [実行の停止と状態確認](../30_detailed_design/01_experiment_api.md)
2. 新しい空の保存先を用意し、プロジェクトルートで下記のようにコピーする。ここでは保存先の例を `/backup/automl/001/` とする。`cp` が正常に完了した一式を復元に使う。

   ```sh
   cp -a data/store/. /backup/automl/001/
   ```

## 復元と確認

1. 復元先の Git クローンで `make venv` を実行し、使用した各版の外部データセットの実体パスを `.env` に記入する。
2. 復元先のプロジェクトルートで、バックアップの中身を空の `data/store/` に戻す。`data/work/` は空から始める。

   ```sh
   mkdir -p data/store
   cp -a /backup/automl/001/. data/store/
   ```

3. `make setup-data` でコーパスのリンクを作成し、再構築できるコーパスの索引を `data/work/` に用意する。
4. 受け入れ条件は、コピー元にアクセスできない状態で、同じ実行 ID から枝・再開元、データセット版、評価結果、ログ、保持した保存点と成果物をバックアップ時点の内容で取得できることとする。設計上は `history` で履歴を確認し、`verify` でプロジェクト全体の記録と成果物を照合する。個々の実行の再現に必要なコード、入力、開始状態、依存環境の照合には `verify --run RUN` を使う。 [別クローンでの復元](../20_basic_design/06_execution_and_replay.md#別のクローンでの履歴の参照と実験の再実行)

## テスト用の正本

通常のテストは Git 管理の小さな入力例・ラベル・レシピから、テストごとに `data/mock/store/` 配下に専用の DB と正本を作る。再構築できる索引や中間ファイルには `data/mock/work/` を使う。復元試験でもこのテスト用正本だけをコピーし、空の作業領域と同じ版の入力から上記の受け入れ条件を確認する。旧版 DB との互換性など、特定の状態を検証する必要が生じた場合は、そのテスト用に作成済みの DB や正本一式を追加できる。
