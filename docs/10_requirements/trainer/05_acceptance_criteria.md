## 要件を満たしたと判断する基準

| ID | 確認する状況と期待結果 | 関連要件 |
|---|---|---|
| `TN-A-001` | データ全体から一括で学習する手法と、複数のモデルを順番に更新する手法を用意する。共通部分を編集せず、設定を切り替えて同じ公開APIから実行できる | `TN-F-001`、`TN-F-002` |
| `TN-A-002` | 再開に対応する手法で、タスクが定めた粒度の保存点から学習を再開する。モデル状態、進捗、データ位置など必要な状態が復元され、同じ条件で中断せずに続けた実行との比較がタスク所定の一致基準を満たす | `TN-F-003` |
| `TN-A-003` | 過去のチェックポイントを初期値に指定して、新しい試行を開始する。指定したモデル状態を引き継ぎ、新規の学習進捗と初期化元を確認できる | `TN-F-004` |
| `TN-A-004` | 完了した試行と途中で失敗した試行について、呼び出し側が適用設定、得られた進捗・指標、生成済みの成果物、終了状態と理由をそれぞれの試行に対応付けられる | `TN-F-005` |
| `TN-A-005` | 再開に対応しない手法、または指定の手法と適合しない保存状態に対して再開を要求すると、呼び出し側が再開できない理由を確認できる | `TN-F-006` |
| `TN-A-006` | 複数の学習時点でロスと統計量を報告し、実行IDから各時点の進捗・指標名・値を取得して推移を比較できる。途中で停止した実行でも、確定済みの時点まで同じように参照できる | `TN-F-005` |
| `TN-A-007` | 2ワーカーを使うTrainerで、片方が停止したら学習を終了する手法を実行する。Trainerが残るワーカーを停止し、終了理由をExperimentに渡す。一つの実行IDから結果と、各プロセスが実際に使ってDatasetに報告したデータを確認できる | `TN-F-005`、`TN-F-007` |
| `TN-A-008` | 分散学習で保存点AのIDを受け取り、各プロセスがその後に使ったデータをDatasetに報告する。次の保存点Bの書き込み途中で実行を停止すると、最後の有効な保存点はAのままで、Aより後の受領済み使用記録も元の実行に残る。再開に対応するTrainerはAからタスク所定の条件で学習を続けられ、再開した実行から元の実行とAを特定できる | `TN-F-003`、`TN-F-005`、`TN-F-007`、`TN-F-008` |
| `TN-A-009` | 有効な保存点Aの後、Bのモデル状態・学習状態・進捗を書き終え、Datasetの使用履歴との対応付けが完了する前に停止する。停止結果に示す再開元と `latest` はともにAを指し、Aより後に受領した使用記録も元の実行から取得できる。最初の保存点で同じことが起きた場合は、有効な保存点がないため再開できないと分かる | `TN-F-003`、`TN-F-006`、`TN-F-008` |
| `TN-A-010` | 更新300のモデルに対する並行評価の結果が更新320で届く。履歴から評価対象の300と到着時点の320を区別できる。300から再開すると、当該結果を参照でき、判断順を再現するTrainerはタスク所定の時点で学習に適用する | `TN-F-003`、`TN-F-005` |
| `TN-A-011` | Trainerが更新300までの使用範囲を指定して保存を依頼し、保存中に更新301の使用記録が届く。保存点に対応する使用範囲は300までで、301の使用分も元の実行履歴から取得できる | `TN-F-008` |
| `TN-A-012` | 同じ実行内で同じ要求ID・内容の保存依頼が同時に届き、さらに確定後の応答消失で再送される。どの応答も同じ保存点IDを返し、保存点と指定範囲の `commit` は各1件となる。同じIDで使用範囲だけを変えると、その相違と `invalid_request` が返り、元の保存点と対応範囲を引き続き参照できる | `TN-F-008`、`TN-F-009` |
