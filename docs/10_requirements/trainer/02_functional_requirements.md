## 機能要件

| ID | 要件 |
|---|---|
| `TN-F-001` | 学習手順の実装とその版、実行設定を指定し、共通の公開APIから学習を開始できること |
| `TN-F-002` | 個別実装がデータの供給、学習目的、モデルの更新順、停止条件を決め、選択された手法に沿って学習を実行できること |
| `TN-F-003` | 再開に対応する個別実装は、プロジェクト・タスクが定めた再開の定義・保存点の粒度に従って、指定した保存点からの再開可否を判定すること。再開時は必要な状態を復元し、タスク所定の一致基準を満たして学習を継続できること。遅れて届いた評価結果をいつ学習に使うかも個別実装が決め、判断順の再現が必要な場合は使用済みの評価を保存時点で特定できること |
| `TN-F-004` | 既存のチェックポイントからモデル状態を初期値として利用し、初期化元を記録した新しい試行を開始できること |
| `TN-F-005` | 実際に適用した学習条件と使用データを試行に関連付けること。タスクの学習成功条件を満たし、全プロセスの実使用データをDBの永続記録から所定の一致基準で復元できることを確認して学習成功を確定すること。学習中にロス・統計量など実装が記録する指標を、その時点の進捗とともに渡せること。成果物の参照、終了状態と理由も同じ試行に関連付けること |
| `TN-F-006` | 実行設定が不適合な場合や、指定された状態からの再開が未対応または不可能な場合に、理由を呼び出し側へ伝えられること |
| `TN-F-007` | 分散学習ではTrainerの個別実装がワーカーの起動・同期・停止を管理し、各プロセスの実使用データと、バッチを使う場合はその構成をDatasetに伝えること。ワーカー停止時の続行可否は個別実装が判断し、Experimentが学習全体を一つの実行として追跡できること |
| `TN-F-008` | Trainerは保存時点を選び、同じ地点のモデル状態・学習状態・進捗をExperimentに渡すこと。再開用の保存依頼には、その状態に反映済みのデータ使用範囲を含めること。状態の保存とDatasetでの指定範囲の対応付けが両方完了してから保存点を有効として公開し、IDを返すこと。どちらかが未完了なら直前の有効な保存点を維持すること |
| `TN-F-009` | 保存依頼には任意の `request_id` を指定できること。同じ実行内で同じID・同じ内容の依頼が複数届いても、保存と `commit` を一度だけ確定し、確定した保存点IDを返すこと。一時的な保存失敗後も失敗理由を履歴に残し、同じID・同じ内容で再試行できること。同じIDでモデル状態・学習状態・進捗・使用範囲のいずれかが変わった場合は、相違した項目を示して `invalid_request` を返し、元の依頼を保持すること |
