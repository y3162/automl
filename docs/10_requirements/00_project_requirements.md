# プロジェクト共通要件

機械学習全般を対象に、エージェントが自律的に実験を進め、人や別のエージェントが過去の条件・結果・判断をたどれる環境を提供する。目標、禁止事項、制約は実験ごとに自然言語で定める。エージェントはその範囲で実験を計画し、必要なコードを作成・変更し、結果をもとに次の試行を選ぶ。

再現可能な学習・評価コードを書く責任は、その実験を実装するエージェントにある。個別実装は、再現に必要な条件や状態を特定して提供する。AutoML はそれらを実行に対応付けて保管し、後から取得し、再実行に利用できる環境を提供する。

## 別の作業ディレクトリでの実験履歴の復元

移行単位はプロジェクト全体とする。進行中の実行を終了または中断してから、同じ計算機上の別のクローンまたは別サーバー上のクローンに正本をコピーする。正本から導出できる情報は復元先で再構築できる。

| ID | 要件 |
|---|---|
| `PR-F-001` | プロジェクトが管理するDBの記録、実行ログ、実験メタデータ、成果物を、別の作業ディレクトリで復元できること |
| `PR-F-002` | 移行前後で、試行の識別子、記録された順序・日時、成功・失敗などの終了状態、設定、指標、試行間の関係および成果物との対応が一致すること |
| `PR-F-003` | 復元時に元の作業ディレクトリへアクセスせず、履歴が参照するDBの記録、ログ、成果物の実体または同じ版に解決できる参照を利用できること |
| `PR-F-008` | プロジェクト全体の移行で対象の評価履歴を復元した場合、呼び出し側が保持する移行前のカーソルで、同じ確定範囲・状態・読み取り位置から分割取得を続けられること |

各モジュールは、自身が扱う履歴や成果物を識別し、復元に必要な情報を提供する。Experimentはそれらを実行に対応付け、移行先で参照と内容を検証する。外部コーパスなどの実体は移行先に同じ版を用意する。正本のコピーと移行先での検証で移行要件を満たす。

## 外部からの実験の反復

外部のAIエージェントが実験結果をもとに仮説を立て、設定や個別実装を変更し、次の実行を選ぶ。実験の起動と履歴の記録にはExperimentの公開APIを使う。

| ID | 要件 |
|---|---|
| `PR-F-004` | 外部の呼び出し元が、履歴の取得、分岐、変更した設定や個別実装を指定した学習・評価の実行、結果の取得を一連の操作として行えること |

## 実験履歴と MLflow

| ID | 要件 |
|---|---|
| `PR-F-005` | 実行IDから、実際に使用したデータ、学習の各記録時点のロス・統計量、使用したモデルの実装・構成・状態、評価対象ごとの結果をたどれること。記録する学習指標と頻度、評価結果の内容は手法に応じて個別実装が定めること |
| `PR-F-006` | 実験記録の正本を AutoML で管理し、比較・可視化に使う項目を選んで MLflow に渡すこと。MLflow を参照せずに実験の詳細履歴を取得でき、連携対象の情報を正本から再登録できること |
| `PR-F-007` | 実行が失敗・中断しても、それまでに確定した学習経過、対象ごとの評価結果、成果物を取得でき、全体の完了状態と区別できること。途中からの続行は対応する個別実装が提供すること |

## 受け入れ基準

| ID | 確認する状況と期待結果 | 関連要件 |
|---|---|---|
| `PR-A-001` | 成功・失敗・チェックポイントからの再開を含む実験履歴を別のクローンに復元する。元の作業ディレクトリを参照せず、DBの記録とログの内容、試行間の関係、指標が復元前と一致し、成果物が同じ内容に解決されることを確認できる | `PR-F-001`、`PR-F-002`、`PR-F-003` |
| `PR-A-002` | 外部の呼び出し元が既存の評価結果を取得し、その履歴から枝を切る。変更したモデルまたは学習手順の個別実装を指定して学習・評価を実行し、分岐元と新しい実行の評価条件・結果を公開APIから取得できる | `PR-F-004` |
| `PR-A-003` | 二つの学習・評価の実行を選び、実際に使用したデータと学習曲線をそれぞれ取得できる。共通のサンプルを一つ選び、両方の評価結果と、それぞれの評価に使ったモデル状態を特定できる | `PR-F-005` |
| `PR-A-004` | MLflow の記録が空でも AutoML から対象ごとの詳細を取得できる。以前に連携した設定・指標を正本から再登録すると、同じ値で実行を比較でき、各実行を AutoML の実行IDに対応付けられる | `PR-F-006` |
| `PR-A-005` | 全100件の評価を完了条件とし、60件の結果が確定した時点で実行を停止する。元の実行からその60件の結果と対象を取得でき、評価全体が未完了と分かる。途中続行に未対応の実装でも同じ基準を満たす | `PR-F-005`、`PR-F-007` |
| `PR-A-006` | 進行中に60件のうち20件を読み、カーソルを保持する。75件で評価を終えてプロジェクト全体を移行した後、別プロセスで同じカーソルを使うと、元の21～60件目と読み出し開始時点の評価状態を取得できる。移行先で新しく読み始めると75件と終了後の状態を参照できる | `PR-F-002`、`PR-F-008` |
