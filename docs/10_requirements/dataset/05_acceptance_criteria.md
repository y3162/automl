## 要件を満たしたと判断する基準

| ID | 確認する状況と期待結果 | 関連要件 |
|---|---|---|
| `DS-A-001` | 元DBにデータを追加しても、固定済みの版から取得する構成は変わらない | `DS-F-002` |
| `DS-A-002` | 生成物の実体を保持しないケースで、DBから取得したレシピと指定版の依存先を使って再生成し、プロジェクト・タスク所定の一致基準を満たすことを確認できる | `DS-F-003`、`DS-F-004` |
| `DS-A-003` | 同じ登録要求を再送しても、登録済みの同じ対象として扱われる | `DS-F-009` |
| `DS-A-004` | 生成されたが学習には使われなかったサンプルを、使用済みとして扱わない | `DS-F-007` |
| `DS-A-005` | 分割間で元データの共有を禁止する個別実装では、同じ元データに由来する生成物が複数の分割に含まれる場合に重複を検出できる | `DS-F-006` |
| `DS-A-006` | レシピの入力素材が取得できない場合、再生成不能であることと原因を確認できる | `DS-F-008` |
| `DS-A-007` | rawデータの保存先を読み取り専用にし、既知のサンプルをDataset経由で取得すると、保存先を直接開くことなく、期待する内容・識別子・メタデータが得られる | `DS-F-010` |
| `DS-A-008` | 新しい保存先に対応するDataset実装を追加し、その実装を設定で指定すると、Datasetの共通部分を編集せずに同じ公開APIからサンプルを取得できる | `DS-F-011` |
| `DS-A-009` | 入力と切り出し位置を学習中に抽選し、同じサンプルを二度使用し、別の一件は先読みだけにする。後日、Dataset がDBだけから各使用分のレシピ（元データのID・版、処理の版、切り出し位置）を取得できる。その版の実体を用いて学習に使った内容を照合でき、使用順序と反復は当時の記録と一致し、先読み分は使用履歴に含まれない | `DS-F-002`、`DS-F-003`、`DS-F-004`、`DS-F-007` |
| `DS-A-010` | 同じバッチでプロセス0が A・B、プロセス1が B・C を使い、プロセス1の記録を再送する。DBからは、バッチ全体で4件（Bの使用は2回）、各プロセスを指定すると元の順に2件ずつ取得できる | `DS-F-007`、`DS-F-012` |
| `DS-A-011` | 4プロセスで構成するバッチで3プロセス分の記録が届いた時点で中断する。DBからその3プロセス分を取得でき、バッチ全体の記録は未完了、残るプロセスの使用状況は未確認と分かる | `DS-F-012`、`DS-F-013` |
| `DS-A-012` | バッチ10までを反映した保存点の確定後、11・12を実際に使って記録し、13を先読みして中断する。元の実行の使用履歴は12まで、再開に使える保存点の範囲は10までと確認できる | `DS-F-007`、`DS-F-014` |
| `DS-A-013` | 音声とラベルを別のDBから組み合わせる個別実装で、ラベルを条件に検索する。該当するサンプルを取得でき、各サンプルから、使用時の音声とラベルそれぞれのID・版を辿れる | `DS-F-001`、`DS-F-005` |
| `DS-A-014` | バッチを定義しない手法でサンプルを使う。バッチの指定を省いて使用を記録し、実行IDから使用した内容を取得できる | `DS-F-007`、`DS-F-012` |

`DS-F-001` と `DS-F-007` を組み合わせた検索は、Transformの `TR-A-008` で確認する。[Transformの受け入れ基準](../transform/05_acceptance_criteria.md)
