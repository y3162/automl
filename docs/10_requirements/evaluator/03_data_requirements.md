## データ要件

| 対象 | 内容 |
|---|---|
| 評価対象 | 評価したモデル状態または入力予測を一意に識別できる情報。モデル状態はチェックポイントへの参照や、その状態を特定できる学習実行・進捗などで表す。後日も重みを復元できるように保持する評価時点はプロジェクト・タスクが選ぶ |
| 入力予測 | プロジェクト内で生成した予測は成果物IDと生成元の実行をたどれること。外部ファイルを使った場合は、評価に使った内容を保存し、その由来を外部入力と記録する |
| 評価条件 | 評価IDから特定できる、実際に適用した評価設定とその版、評価手順・指標の実装と版、評価単位、集計方法、評価データの版と分割、適用したTransform、エラー時の対応、評価全体の完了条件 |
| 評価結果 | 指標値と集計結果、終了状態と完了条件の判定、必要に応じて暫定値であることを示す情報 |
| 評価対象の内訳 | 評価予定の範囲、実際に集計した対象、失敗・除外した対象とその理由を特定できる情報。対象は、評価手順に応じてサンプル、グループ、区間などで特定する |
| 対象ごとの結果 | 評価ID、その評価内の測定結果ID、対象の識別情報、対象について確定した予測やスコアなど。各結果から、実際に使用したデータと、評価したモデル状態または入力予測を特定できる情報。たとえば話者別スコアでは話者IDと、計算に使った各発話を特定できる参照 |
| 続行・訂正・再集計 | 新旧の評価を特定する実行ID・評価ID、採用した各結果の出所と対象、適用した集計条件。訂正時は訂正元・訂正理由も保持する。版をまたぐ比較では各対象のデータセット版・サンプルIDと、タスクで対応付けた対象を特定できること |
| 並行評価 | 評価対象となった学習実行・モデル状態と、結果の到着時点。評価結果が学習判断に使われる時期はタスクの再開条件に従う |
| ログ | ログを生成した場合の内容と評価ID。項目と頻度は個別実装が定める |
