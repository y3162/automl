## 要件を満たしたと判断する基準

| ID | 確認する状況と期待結果 | 関連要件 |
|---|---|---|
| `EV-A-001` | 契約に適合する評価実装を追加し、共通部分を編集せずに設定で選べる。同じ実装と設定を学習中にも単独でも、同じ公開APIから利用できる | `EV-F-001` |
| `EV-A-002` | 対象モデルと評価条件を指定すると、実際に適用された設定、指標と集計結果、完了状態が返り、評価対象と結果を対応付けられる | `EV-F-002` |
| `EV-A-003` | 評価中にエラーが起こる入力で、再試行・打ち切り・続行を設定で切り替えると、指定された対応が実行される | `EV-F-003` |
| `EV-A-004` | 同じ評価設定で集計件数が等しく、集計した対象が異なる二つの結果から、その違いと各失敗・除外の理由を確認できる。完了条件を満たさず集計値が返った場合は、暫定値と分かる | `EV-F-004` |
| `EV-A-005` | 同じEvaluatorを学習中と単独で呼び、評価中と終了時に共通の受け口に渡したログを、それぞれの評価IDから取得できる。途中で停止した場合も、その評価でExperimentが受領したログを取得できる | `EV-F-001`、`EV-F-005` |
| `EV-A-006` | 同じデータを二つのモデル状態で評価し、指定したサンプルの結果を状態ごとに取り出して比較できる。一方の評価が途中で停止しても、それまでに確定した各サンプルの結果を取得できる | `EV-F-002`、`EV-F-006` |
| `EV-A-007` | 予定した話者10人全員の評価を完了条件とし、ログを出さずに話者単位で評価する。6人分のスコアが確定した時点で停止しても、元の評価IDからその6人のスコアと適用した評価条件を取得できる。各スコアから、話者ID、計算に使った発話、評価したモデル状態を辿れ、評価全体は未完了と分かる | `EV-F-002`、`EV-F-004`、`EV-F-006` |
| `EV-A-008` | 更新300のモデルで並行評価を開始し、評価途中にTrainerが更新301へ進む。後半の対象も更新300の状態で評価され、全結果からその状態を特定できる。更新300の重みを長期保管しない設定でも、履歴でこの対応を確認できる | `EV-F-001`、`EV-F-006` |
| `EV-A-009` | 同じ評価内の結果 `r60` を0.80として二度報告しても1件となる。0.85で同じIDを再送すると対象と相違を返し、0.80を保持する。新しい結果IDで実際に再測定すれば別件として取得できる | `EV-F-006`、`EV-F-007` |
| `EV-A-010` | 60件の時点から分割取得中に75件まで増えても、その取得では元の60件を一度ずつ読め、追加15件は次の取得で読める。別の評価を60件で中断した後、記録済みの同一再送には元の記録を返し、遅れて届いた未登録の61件目を採用する場合は新しい評価IDに記録する | `EV-F-007`、`EV-F-008` |
| `EV-A-011` | 中断前の60件と続行側の測定から100件を集計する。重複対象を再測定していても、元の評価の60件は残り、集計から各対象について採用した評価ID・測定結果を特定できる | `EV-F-006`、`EV-F-008` |
| `EV-A-012` | ラベル誤りの1件を訂正し、元の99件を再利用する。訂正版から訂正元・理由・採用した100件をたどれ、元の集計値、元の評価に基づく判断・分岐、元評価から訂正版への参照を確認できる | `EV-F-008` |
| `EV-A-013` | 旧版100件・新版90件の評価で、対応が確かな80件を再集計する。版内の同じサンプルIDだけでは同一対象と判定せず、確認できない対応は不明とする。試算を参照用の結果として保存したとき、新しい評価IDから元の両評価、採用した80件と条件をたどれ、元の集計も残る | `EV-F-004`、`EV-F-008` |
