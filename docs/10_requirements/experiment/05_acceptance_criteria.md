## 要件を満たしたと判断する基準

| ID | 確認する状況と期待結果 | 関連要件 |
|---|---|---|
| `EX-A-001` | 既存のモデル状態と評価設定を指定した評価のみの実行では、Evaluatorだけが起動し、評価対象、結果、ログを実行IDに対応付けられる | `EX-F-001`、`EX-F-005` |
| `EX-A-002` | 履歴上の同じ地点から同じ設定で、異なる要求IDを使って二度やり直すと、それぞれ別の枝IDと実行IDが割り当てられる。両方の枝から共通の分岐元をたどれ、元の枝からは両方の分岐を確認できる | `EX-F-002`、`EX-F-003`、`EX-F-011` |
| `EX-A-003` | 中断した学習をチェックポイントから再開すると、同じ枝の末尾に別の実行IDで履歴が追加され、中断した実行と再開元のチェックポイントを確認できる | `EX-F-002`、`EX-F-003` |
| `EX-A-004` | 学習が成功し評価が失敗した実行で、学習の結果と成果物、評価の失敗理由、渡されたログを確認できる。保存したモデルを使って評価のみを再実行し、両方の評価履歴をたどれる | `EX-F-001`、`EX-F-004` |
| `EX-A-005` | 実行IDから、実際に適用した設定と実装の版、データの版、初期状態、結果、ログ、成果物の対応を確認できる | `EX-F-005` |
| `EX-A-006` | 同じ評価結果を複数の判断に利用したことを記録し、各判断から同じ評価結果を参照できる | `EX-F-006` |
| `EX-A-007` | 成功・失敗・再開・分岐を含むプロジェクトで、進行中の実行を終了または中断し、全体の正本を別の計算機へコピーする。外部コーパスは同じ版を用意する。移行元に接続せず、同じ実行IDから分岐元・再開元・評価結果・保持対象の成果物を辿れ、全枝と実行のID・順序・関係、DBの記録、ログ、成果物の内容が移行前と一致する | `EX-F-007` |
| `EX-A-008` | 外部の呼び出し元が公開APIで履歴を取得し、指定した地点から枝を作り、確保済みの計算機で実行を起動する。起動を依頼したセッションを閉じた後も、別のセッションから受付時の実行IDで状態と結果を取得でき、作成した枝とその分岐元を辿れる | `EX-F-001`、`EX-F-008` |
| `EX-A-009` | 移行先のコピーで、履歴にある保持対象のチェックポイントが欠けている場合と、内容が保存時と異なる場合を検証する。どちらも移行元に接続せず、該当する実行・成果物と、不足または内容不一致の理由を確認できる | `EX-F-007` |
| `EX-A-010` | 同じ枝への別々の起動要求が重なると、一件を受け付け、もう一方には進行中の実行IDと受付できない理由を返す。その実行中に別の枝で起動した実行は、それぞれのIDで並行して追跡できる | `EX-F-002`、`EX-F-008` |
| `EX-A-011` | 同じ計画で学習が先に成功し、並行評価が続く間は学習が「成功」、実行全体が「実行中」と分かる。そのまま評価が完了条件を満たせば全体は成功となる。評価の途中で停止を要求して打ち切った場合は、学習の成功と成果物を保持し、評価と全体は中断となる | `EX-F-004`、`EX-F-009`、`EX-F-010` |
| `EX-A-012` | 学習と評価が並行する実行に停止を要求する。両方の停止を確認して全体が中断となり、確定済みの指標・対象別結果・使用履歴・成果物を取得できる。再開に未対応のTrainerでも停止でき、履歴から再開できない理由を確認できる | `EX-F-004`、`EX-F-010` |
| `EX-A-013` | 後日、保存済みのモデル状態または入力予測を使って評価だけを起動する。新しい実行IDから元の学習実行と評価対象を特定できる。そのIDに停止を要求すると評価は中断し、元の実行の終了状態と当時の結果を引き続き取得できる | `EX-F-001`、`EX-F-009`、`EX-F-010` |
| `EX-A-014` | 枝作成・起動・再開のそれぞれで、受付後に応答が途切れ、同じ要求IDと内容で再送する。枝作成は初回の枝ID、起動・再開は初回の実行IDを返す。実行中と終了後のどちらに再送しても、履歴上の件数は増えない | `EX-F-011` |
| `EX-A-015` | 保存点Aからの分岐と起動を一度に依頼し、同じ要求IDと内容が同時に二度届く。枝と実行は各一件で、どちらの応答も同じ枝ID・実行IDを返す。その要求IDで分岐元をBに変更した場合は理由付きで拒否され、Aからの枝と実行を引き続き参照できる | `EX-F-002`、`EX-F-011` |
| `EX-A-016` | 更新300の保存点に対する並行評価が失敗し、学習はその評価に依存せず続行できる。評価は `failed`、学習と実行全体は `running` となる。学習が成功すると実行全体は `failed` となり、学習の成果物と評価の失敗理由を確認できる | `EX-F-004`、`EX-F-012` |
| `EX-A-017` | 更新350で学習が失敗し、更新300の保存点に対する並行評価は続行できる。学習は `failed`、評価と実行全体は `running` となる。評価が成功すると実行全体は `failed` となり、評価結果から更新300の保存点を特定できる | `EX-F-004`、`EX-F-012` |
| `EX-A-018` | 逐次計画で評価の開始前に学習が失敗する。その時点で実行全体と学習は `failed`、評価は `skipped` となり、「前段の学習が失敗したため」と確認できる。有効な保存点から後日評価すると、新しい実行IDでその結果を参照できる | `EX-F-009`、`EX-F-012` |
| `EX-A-019` | 並行評価の失敗後に学習の停止を要求する。安全な停止を確認すると、評価は `failed`、学習は `interrupted`、実行全体は `failed` となる。学習が先に失敗し、並行評価を停止した場合も、学習は `failed`、評価は `interrupted`、実行全体は `failed` となる。どちらも履歴から各処理の終了理由を確認できる | `EX-F-004`、`EX-F-010`、`EX-F-012` |
| `EX-A-020` | 逐次計画で後続評価の開始前に学習の停止を要求する。学習の安全な停止を確認した時点で、実行全体と学習は `interrupted`、評価は `skipped` となり、履歴に「前段の学習が中断されたため」と記録される。学習成功後、すでに開始した評価を停止した場合は、評価は `interrupted` となる | `EX-F-004`、`EX-F-010` |
| `EX-A-021` | 更新400の保存点を削除し、300だけが利用可能な場合、過去の比較には400を含められ、重みを使う順位付けの候補は300となる。400を明示した利用には削除済みの理由を返す。`latest` からの再開には300を記録し、残る候補も削除すれば再開できない理由を返す | `EX-F-003`、`EX-F-013`、`EX-F-014` |
| `EX-A-022` | 保存点Aを使う2件を受け付け、一方でも開始状態のコピー中なら削除は「使用中」で終わる。全コピー完了後は評価の終了前でも再依頼によりAを削除できる。先に削除が確定したAを使う依頼は削除済みと分かる | `EX-F-014` |
| `EX-A-023` | Aのモデル状態を削除した直後に停止する。Aは削除中として新規利用から外れ、同じIDの再依頼で残る学習状態も削除される。再度依頼すると削除済みと分かる。移行先の検証では削除済み、削除中、保持対象の欠落を区別し、Aの利用側が保持する開始状態の欠落も検出する | `EX-F-007`、`EX-F-014` |
| `EX-A-024` | 学習に成功した2実行で評価候補がともに0件となる。意図に従って見送った報告では評価は `skipped` で全体は `succeeded`、必要な評価を実施できなかった報告では評価・全体は `failed` となる。どちらも学習の成功と報告理由を確認できる | `EX-F-004`、`EX-F-013` |
| `EX-A-025` | 更新350で中断し、300から350まで再開した履歴から、モデルに至る350更新と計算した400更新の各区間を取得できる。別の枝が300の重みから50更新した場合は、その50更新と初期化元を個別にたどれる | `EX-F-003`、`EX-F-015` |
