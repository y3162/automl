## 機能要件

| ID | 要件 |
|---|---|
| `EX-F-001` | 初版では確保済みの計算機上で、設定で指定した学習・評価を公開APIから別プロセスとして起動できること。評価のみの実行では、指定したモデル状態や予測結果をEvaluatorに渡すこと |
| `EX-F-002` | 枝と実行に一意で安定したIDを割り当て、枝内の順序と分岐元を記録し、各地点から起点までの経路と、その地点から分岐した枝をたどれること。同じ枝では一度に一実行を受け付け、別の枝では並行実行できること |
| `EX-F-003` | 中断からの再開を同じ枝の末尾に追加できること。過去の地点や共通の起点からやり直す場合は、設定が同じでも新しい枝を作成できること |
| `EX-F-004` | 実行と各処理の状態・結果を個別に記録すること。処理中の失敗・中断でも、それまでに確定した対象別の結果、学習経過、ログ、成果物を保持し、それらを使った後続の実行を追跡できること |
| `EX-F-005` | 実際に適用された設定、コードと実装の版、データやモデル状態の参照、TrainerやEvaluatorから渡された結果・ログ・成果物を、それぞれの実行に関連付けて記録・検索できること |
| `EX-F-006` | 呼び出し側が報告した判断と、その判断に用いた評価結果を関連付けて記録できること |
| `EX-F-007` | プロジェクト全体の正本をコピーした移行先で、移行元に接続せずに、同じ実行IDから枝・実行・評価結果・保持対象の成果物を辿れ、DBの記録、ログ、成果物の内容と関係を検証できること。不足や不一致があれば、対象と理由を特定できること |
| `EX-F-008` | 外部の呼び出し元が、公開APIから枝と実行履歴を取得し、指定した地点から枝を作成できること。その枝で実行を起動し、実行IDを使って状態と結果を取得できること |
