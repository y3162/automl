# 設定と個別実装

Experimentが個別実装を読み込み、実行に使う設定を確定するまでの流れを定める。[実行フロー](01_execution_flow.md)

## 実装の指定

設定に、使用する個別実装への参照と、その実装に渡す設定を書く。Experimentは指定された参照から実装を直接インポートし、使用する版と公開APIの契約への適合を確認する。設定項目、既定値、許容される値は個別実装が定める。

たとえば `src/methods/baseline_mlp/model.py` に `Model` を実装する `MLP` を置いた場合、子configの `components.model.implementation` に `methods.baseline_mlp.model.MLP` を指定する。Trainer・Evaluatorが求める操作を提供していれば、同じ学習・評価手順で利用できる。Trainer・Evaluatorの個別実装からは、`automl.experiment` の `Components` で設定された部品を構築し、`RunContext` を通じてログや保存点を渡せる。

## 実装者による版管理

実装者は、過去の実行で指定した版を後から選んでも、当時の処理を呼び出せるように管理する。版ごとにディレクトリやファイルを分ける方法、同じ実装で版を引数として受け取る方法など、区別の仕方は実装者が選ぶ。Experimentは実装の参照と版を選ぶために使った設定を実行履歴に残す。

この契約は、別の版から import した補助モジュールにも適用する。たとえば新版で正規化を変える場合、新版から変更後の処理を呼び、旧版を選ぶ設定では従来の計算を使えるようにする。過去の実行そのものを再現するときは、確定設定と、その実行の受付時に固定したソースを使う。 [手法の配置と実装の版管理](../90_operations_and_maintenance/03_source_layout_and_versions.md)

## 設定の継承

設定を再利用する場合は、親configを明示し、今回の変更を子configに書く。過去の実行で保存された確定済みconfigも、親として指定できる。

- 同じ実装を使う部品は親の設定を引き継ぎ、子で指定した項目を上書きする。
- 別の実装に差し替えた部品は、設定を丸ごと置き換える。新しい実装の既定値に、子で明示した値を適用する。旧実装の設定値を使いたい場合は、子にその値を書く。

たとえば、親configからDatasetとEvaluatorを引き継ぎ、Modelだけを差し替える場合、DatasetとEvaluatorは親の設定を使う。Modelには、新しい実装で定義された既定値と子に書いた値が適用される。

## 確定済みconfigと履歴

Experimentは、継承と上書きを解決し、各実装の既定値を反映した設定を検証してから、実行を受け付ける。確定済みconfigは実行ごとのファイルとして保存する。実行IDから適用設定と実装の版をたどれ、親や子のファイルを後から編集しても、その実行で使った設定を確認できるようにする。計算機間での移動時は、確定済みconfigも実行履歴とともに引き継ぐ。[履歴と成果物](02_history_and_artifacts.md)

枝の分岐元はExperimentが履歴に記録し、設定の継承元は親configで指定する。モデルの重みやモデル固有の状態を引き継ぐときは、初期化元のチェックポイントと引き継ぎ条件を指定する。構造の変更や一部の再初期化を伴う場合は、Modelの部分初期化を使う。[Modelの機能要件](../10_requirements/model/02_functional_requirements.md)
