# チェックポイントと学習再開

チェックポイントを再開に使える条件と、保存された状態から学習を始める方法を定める。[Trainerの機能要件](../10_requirements/trainer/02_functional_requirements.md)

## 有効な保存点

学習の再開の定義、対応の要否、保存点の粒度、中断せずに続けた場合との一致基準はプロジェクト・タスクごとに定める。対応するTrainerは、その条件で学習を続けられる地点を保存点として示す。必要な学習状態の内容・形式と進捗の表し方は個別実装が決める。

Trainerは同じ地点のモデル状態・学習状態・進捗を揃える。学習状態には、手法に応じてデータ位置、乱数、最適化器などの状態を含める。再開可能な保存点として公開する条件は、これらの状態の保存と、その地点に反映された使用履歴の範囲をDatasetに対応付ける操作（`commit`）の両方が完了することである。Experimentは完了を確認して保存点を有効として履歴に登録し、`latest` を更新して保存点IDを返す。

たとえば保存点Aの次にBのモデル状態・学習状態・進捗を書き終えても、使用履歴の対応付け中に停止した場合はAが `latest` のままとなる。A以降にDatasetが受領した使用記録は元の実行に残る。中断した学習の履歴には、再開可能ならAのIDを、手法が再開に未対応または有効な保存点が一つもない場合はその理由を記録する。

## 更新される保存点の参照

`latest` は現在保持している再開可能な保存点のうち、学習順で最後の保存点を指す。成績に応じた選択や保持はプロジェクト・タスク側で行い、選択した保存点IDをExperimentに渡す。[保存点の選択と保持](../30_detailed_design/04_checkpoint_management.md#保存点の選択と保持)

再開・初期化・評価に使うときは、指定名と解決した保存点の成果物IDを履歴に記録する。利用側の実行は、そこから準備した実際の開始状態を独立して保存する。生成元が旧世代を整理した後も、利用側の履歴からその実行の開始状態を復元できる。[履歴と成果物](02_history_and_artifacts.md)

## 同じ枝での再開

中断した実行で現在も保持している最後の再開可能な保存点から、元の実行と同じ学習条件で続ける。適用設定、モデル構成、学習手法、実装の版、使用データの版を引き継ぎ、開始状態は選んだ保存点から復元する。Modelがモデル状態をロードし、Trainerが対応する学習状態を復元する。再開に必要な状態が取得できない場合や、元の学習条件と一致しない場合は理由を呼び出し側に伝える。

Experimentは同じ枝の末尾に新しい実行IDを追加し、再開元の実行IDと保存点IDを記録する。最後の有効な保存点より後に受け取ったログやDatasetの使用記録も、中断した実行の履歴から参照できる。計算機間の移動で保存場所が変わった場合も、同じ学習条件と保存状態を取得でき、タスクの再開条件を満たせば同じ枝で再開できる。[実行フロー](01_execution_flow.md) · [履歴と成果物](02_history_and_artifacts.md)

## 新しい枝での試行

以前の保存点から意図的にやり直す場合や、学習条件を変えて続きを試す場合は、新しい枝を作る。モデル状態を引き継ぐ場合は、初期化元のチェックポイントと引き継ぎ条件を指定し、新しい手法に従って学習状態を初期化する。モデル構造の変更や一部の再初期化を伴う場合は、Modelの部分初期化を使う。Experimentに分岐元と初期化元を記録する。[Modelの機能要件](../10_requirements/model/02_functional_requirements.md)
