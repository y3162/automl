# 実行基盤と履歴の参照

## 起動と監視

初版では、呼び出し側が確保した計算機上でExperimentが学習・評価を受け付け、その計算機の別プロセスで起動する。受付時に返す実行IDで追跡が始まる。依頼したエージェントやCLIのセッションを閉じても実行は継続し、別のセッションから同じ実行IDで状態と結果を取得できる。[実行フロー](01_execution_flow.md)

## 中断と異常終了

学習・評価を中断するときは、呼び出し側が実行IDを指定してExperimentに依頼する。その実行の進行中の処理は安全に終了できる地点で停止し、Experimentが停止を確認して中断を記録する。再開に対応しない学習でも停止できる。中断した学習の履歴には、利用できる保存点または再開できない理由を残す。[中断要求](../30_detailed_design/03_execution_state_and_processes.md#中断要求)

実行プロセスが予期せず止まった場合は、Experimentが異常終了を確認して失敗を記録する。取得できた終了理由・ログ・成果物は保持する。保存を完了できなかった場合も、最後の有効な保存点があれば、対応するTrainerがタスクの条件に従ってそこから再開できるかを判定する。再開を依頼するかどうかは、失敗の記録を見たユーザーやエージェントが決める。[チェックポイントと学習再開](05_checkpoints_and_resume.md)

## 別のクローンでの履歴の参照と実験の再実行

同じ計算機上の別ディレクトリや、別サーバーに作ったクローンを移行先にできる。移行元で進行中の実行を終了または中断し、正本への書き込みが止まった状態で、ユーザーが `data/store/` 一式をコピーする。全枝の実行履歴と評価結果、DBの記録、確定設定、ログ、保持対象のチェックポイントなどの成果物を引き継ぐ。実行のイベントと診断成果物もストアに含める。移行先では使用時と同じ版の外部コーパスを同じ入口から参照し、索引やキャッシュは空の `data/work/` から再構築できる。 [Dataset のデータ配置](../30_detailed_design/05_dataset.md#データ配置とコーパスの入口)・[復元手順](../90_operations_and_maintenance/01_data_and_backup.md#復元と確認)

- 移行元に接続せず、同じ実行IDから状態、分岐元・再開元、評価結果、ログ、成果物を辿れる。
- 移行先の `verify()` は、プロジェクト全体の履歴と保持対象の成果物を照合して検証件数を返す。見つかった不整合は `issues` にまとめ、項目ごとに該当する実行IDや成果物IDと理由を示す。削除が未完了の保存点はIDとともに報告し、ほかに不整合がなければCLIは終了コード `0` を返す。保持対象の欠落や内容の不一致があれば `1` を返す。[Experimentの公開インターフェース](../30_detailed_design/01_experiment_api.md#成果物の整合性検証)
- **実験の再実行**。確定済みconfigとコード・データの版、必要な状態をたどり、同じ条件で学習や評価を再実行できる。結果は実験で定めた一致条件に従って照合する。

実行履歴の保存形式と記録方式は実装ごとに選べる。ローカル実装は SQLite にイベントを記録する。どの方式でも、同じ枝への同時要求は一件だけ受け付け、枝の占有と実行の登録を一つの操作として扱う。[実行状態とプロセス管理](../30_detailed_design/03_execution_state_and_processes.md)

依存環境について照合する項目と一致基準はプロジェクト・タスクが定める。実行時に対象項目の値を記録し、移行先の `verify(run)` で照合する。たとえばPyTorchのバージョンがタスクの基準を満たさなければ、`ready` は `false` となり、`issues` から項目名、実行時の値、移行先の値を確認できる。

XOR では実行を終了または中断し、同じ依存環境を用意した同一リポジトリの別クローンに `data/store/` をコピーする。`history` と `verify` で履歴を照合し、`verify --run RUN` でその実行の復元に必要な材料を照合する。保存点を直接指定して再評価すると、その保存点を作った実行の評価条件を引き継ぐ。過去の評価を分岐元にして同じ保存点を指定すると、その評価で使った条件を引き継ぐ。[実行計画と起動時の指定](../30_detailed_design/01_experiment_api.md#実行計画と起動時の指定)

Experimentは各実行で使うプロジェクトソースを受付時に固定する。`src/` やルート直下のモジュール・パッケージを含め、実行に使ったソースを未コミットの追加・編集・削除も反映した状態で復元できる情報を `data/store/` に保持する。たとえば実験用のGitブランチを後日削除して元のコミットを取得できなくなっても、移行先では正本から当時のファイル構成と内容を復元できる。

保存方式は未決とする。たとえば実行時のソース一式を保持する方法と、共有する基準ソースと各実行のパッチを正本に保持する方法がある。[プロジェクト共通要件](../10_requirements/00_project_requirements.md#別の作業ディレクトリでの実験履歴の復元)

実行ごとの `replay.json` が実装と Dataset の入力版を指す。受付時の検証・worker・再開は復元したコードを使用する。設定に含まれるデータパスは引き続きプロジェクトルート基準とする。展開済みソースは通常運用では `data/work/automl-source/` に、自動テストでは `data/mock/work/` 配下のテスト専用領域に再構築できる。外部コーパスは移行先に同じ版を用意し、依存パッケージはプロジェクト・タスクの一致基準を満たす環境を用意する。

コードを記録していない旧形式の run を再開した場合、再開に使った現在のソースを固定し、元の版を特定できない親の ID を `unrecorded_parent_source` に残す。
