# 実行基盤と履歴の参照

## 起動と監視

初版では、呼び出し側が確保した計算機上でExperimentが学習・評価を受け付け、その計算機の別プロセスで起動する。受付時に返す実行IDで追跡が始まる。依頼したエージェントやCLIのセッションを閉じても実行は継続し、別のセッションから同じ実行IDで状態と結果を取得できる。[実行フロー](01_execution_flow.md)

## 中断と異常終了

学習・評価を中断するときは、呼び出し側が実行IDを指定してExperimentに依頼する。その実行の進行中の処理は安全に終了できる地点で停止し、Experimentが停止を確認して中断を記録する。再開に対応しない学習でも停止できる。中断した学習の履歴には、利用できる保存点または再開できない理由を残す。[中断要求](../30_detailed_design/03_execution_state_and_processes.md#中断要求)

実行プロセスが予期せず止まった場合は、Experimentが異常終了を確認して失敗を記録する。取得できた終了理由・ログ・成果物は保持する。保存を完了できなかった場合も、最後の有効な保存点があれば、対応するTrainerがタスクの条件に従ってそこから再開できるかを判定する。再開を依頼するかどうかは、失敗の記録を見たユーザーやエージェントが決める。[チェックポイントと学習再開](05_checkpoints_and_resume.md)

## 別のクローンでの履歴の参照と実験の再実行

同じ計算機上の別ディレクトリや、別サーバーに作ったクローンを移行先にできる。移行元で進行中の実行を終了または中断してから、ユーザーがプロジェクト全体の正本をコピーする。全枝の実行履歴と評価結果、DBの記録、確定設定、ログ、保持対象のチェックポイントなどの成果物を引き継ぐ。実行のイベントと診断成果物もストアに含める。外部コーパスは移行先に同じ版を用意し、同じ入口から参照できるようにする。正本から導出できる索引やキャッシュは移行先で再構築できる。[Datasetのデータ配置](../30_detailed_design/05_dataset.md#データ配置とコーパスの入口)

- 移行元に接続せず、同じ実行IDから状態、分岐元・再開元、評価結果、ログ、成果物を辿れる。
- 移行先では履歴の参照先を確認し、保持する成果物を保存時の内容と照合する。保持対象のチェックポイントに欠落や内容の不一致があれば、検証結果から該当する実行・成果物と理由を確認できる。[Experimentの公開インターフェース](../30_detailed_design/01_experiment_api.md#成果物の整合性検証)
- **実験の再実行**。確定済みconfigとコード・データの版、必要な状態をたどり、同じ条件で学習や評価を再実行できる。結果は実験で定めた一致条件に従って照合する。

実行履歴の保存形式と記録方式は実装時に選ぶ。どの方式でも、同じ枝への同時要求は一件だけ受け付け、枝の占有と実行の登録を一つの操作として扱う。[実行状態とプロセス管理](../30_detailed_design/03_execution_state_and_processes.md)

XOR では実行を終了または中断し、同じ依存環境を用意した同一リポジトリの別クローンに `data/store/` をコピーする。`history` と `verify` で履歴を照合し、`verify --run RUN` でその実行の復元に必要な材料を照合する。`start --branch BRANCH --evaluate CHECKPOINT_ID` は保存元の条件で再評価する。[成果物の整合性検証](../30_detailed_design/01_experiment_api.md#成果物の整合性検証)

受付時に Git の基準コミットと実行時のプロジェクトソースのバイナリ差分を固定する。対象は `src/`、ルート直下の Python モジュールとパッケージで、追跡済みファイルの編集・削除、Git の除外対象外の新規ソースを含む。差分は `sources/` に内容ごとに一度だけ置く。ローカルのリモート追跡参照から基準 SHA に到達できる場合、復元先はその Git オブジェクトを使う。到達できない場合は基準ソースも同梱する。Git 管理外のプロジェクトでは空の基準から記録する。

実行ごとの `replay.json` が実装と Dataset の入力版を指す。受付時の検証・worker・再開は復元したコードを使用する。設定に含まれるデータパスは引き続きプロジェクトルート基準とする。展開済みソースは `data/work/automl-source/` に再構築できる。外部コーパスやインストールしたパッケージは移行先に同じ版を用意する。

コードを記録していない旧形式の run を再開した場合、再開に使った現在のソースを固定し、元の版を特定できない親の ID を `unrecorded_parent_source` に残す。
