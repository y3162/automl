# Modelの詳細設計（SS）

## モデルの構築

モデルの実装・版と構成設定にはDataset・Transformと同じ指定方式を使う。Experimentは指定された実装・版を解決し、個別実装の既定値を反映した設定を検証する。実行IDから実装の参照・版、確定設定、読み込んだモデル状態を辿れるようにする。[設定と個別実装](../20_basic_design/03_configuration_and_implementations.md)

公開API `build` は、指定された実装と構成からモデルを構築する。呼び出し側は次の構築方法のいずれかを明示する。アーキテクチャ、元の状態と構築先の状態の対応付け、初期化処理は個別実装が定める。構築後の推論などの操作と入出力はプロジェクト・タスクの契約に従い、Trainer・Evaluatorがそれぞれ必要な条件を確認する。[Modelの機能要件](../10_requirements/model/02_functional_requirements.md)

| 構築方法 | 動作 |
|---|---|
| 新規初期化 | 指定した構成のモデルを作り、指定した条件で初期化する。 |
| 完全復元 | 保存点から重みとモデル固有の状態を復元する。同じ枝での再開や、保存済みモデルの評価に使う。必要な状態が欠けている場合や構成に適合しない場合は、理由を伝えて失敗する。 |
| 部分引き継ぎ | 新しい構成のモデルを作り、保存点から初期化設定で指定した重みとモデル固有の状態を引き継ぐ。構築先の残りは指定した条件で初期化し、引き継いだ箇所と初期化した箇所を呼び出し側に返す。指定箇所の一つでも欠落または不適合で引き継げなければ構築は失敗し、モデルを返さずに該当箇所と理由を伝える。Trainerは開始状態を保存せず、学習を開始しない。 |

たとえば別枝で分類ヘッドを交換し、`retain` に `encoder` を指定した場合、TrainerはModelの `build` の初期化設定にその指定名を渡す。個別のModelが `encoder` に対応する重み・状態を特定し、新しいヘッドを初期化する。正規化層の学習済み統計量も引き継ぐか、再初期化するかは、そのModelの初期化設定に従う。評価のみの実行で完全復元を指定した場合は、必要なヘッドの重みや統計量が欠けていればモデル構築の時点で失敗する。

## 保存点に渡すモデル状態

Modelは構築済みモデルから現在のモデル状態を取り出す公開操作を提供する。個別実装は、対応する実装と構成の `build` で完全復元できるよう、必要な内容と形式を定める。たとえば推論時に学習済みの統計量を使うモデルでは、その統計量も重みとともに渡す。

保存点には、保存を依頼した時点の重みとモデル固有の状態を一緒に記録する。たとえば更新300の保存中に学習が更新301へ進んでも、その保存点からは更新300の重みと統計量を復元できる。状態をコピーして学習を続けるか、書き込みが終わるまで次の更新を待つかなど、その時点の状態を保つ方法は個別実装が決める。

Trainerは保存のタイミングを決め、この操作で取得したモデル状態と、同じ地点のTrainer自身の学習状態をExperimentに渡す。Experimentは両者を対応付け、必要な状態が揃った保存点を履歴に記録する。学習開始状態の保存にも、学習途中の保存にも、同じモデル状態の取得操作を使う。[保存点と実行開始状態](04_checkpoint_management.md)
